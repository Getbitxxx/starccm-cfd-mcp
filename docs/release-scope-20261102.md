# 发布作用域（窄发布）2026-11-02

**一句话：** 发布集合不再等于"磁盘上所有 Python 文件"，而是由 `release-scope.json` 声明的子集；被挂起的文件在 manifest 里逐个点名，且构建对"挂起但仍被需要"的情况 fail-closed。

## 解决的问题

`code_files()` 原本递归收 `scripts/`、`cases/`、`cad/` 下**全部** `*.py`。后果是每次发布都顺带把本轮没碰过的一次性脚本一起"批准"：

- 2026-11-02 第一次发布：审查要签 **121** 条哈希，其中 34 个文件与改动无关；
- 上一轮独审的原话：**"审 3 个文件却要签 121 个哈希，就是把全量断言变成假陈述"**；
- 结果是要么花时间全树审，要么找个理由绕过——两种都在消耗这套机制的信用。

## 机制

`release-scope.json`（项目根）：

```json
{"schema_version": 1, "reason": "为什么挂起这些", "hold": ["scripts/xxx.py", ...]}
```

- `hold` 里的文件**不进 manifest**，但仍留在工作树，并在 `manifest.scope.held` 里**逐个点名**。
- 没有该文件时保持旧行为（发布全部），所以老项目不会被这次改动破坏。
- 校验一律 fail-closed：

| 情况 | 结果 |
|---|---|
| 未知键 / `hold` 不是非空字符串列表 | 拒绝构建 |
| 某个 pattern 匹配不到任何文件（拼写错误） | 拒绝构建 |
| 挂起了 `scripts/server_v2.py`（业务入口） | 拒绝构建 |
| 挂起了 `GATEWAY_FILES`（网关/发布管理器） | 拒绝构建 |
| 挂起的文件**被发布代码 import** | 拒绝构建，报出两侧文件名 |
| 挂起的文件名**出现在发布代码文本里**（按路径/名字引用） | 拒绝构建，报出两侧 |

## 代价（必须知道）

1. **`UNPUBLISHED_CODE` 不再覆盖被挂起文件**。它们从 `manifest['files']` 消失，改动它们不会阻断写操作。
   这是设计的一部分（它们不在任何工具执行路径上），但意味着"挂起"是**安全边界**而不是"待办列表"：
   一个脚本如果要被业务路径用到，必须先移出 `hold`、重新发布、重新独审。
2. **字号是唯一证据**：`manifest.scope` 记录 `hold`、`held`、`published`、`held_count` 与 scope 文件自身的 sha256。
   注意 `scope` **不参与 `release_id` 计算**（`release_identity` 只取 6 个键），所以改 scope 必须走新版本 + 新独审，
   不能靠"只改一个 JSON"。
3. 静态闭包看不见动态导入。`_imports_of` 只解析 `import` / `from`；`importlib`、`getattr(__import__…)` 之类不会被守卫发现。
   当前仓库里的动态装载目标都在发布集内，但这是**可用性**风险，不是完整性保证。
